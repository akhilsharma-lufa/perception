Perception Math and Stability Guide

Scope: current perception package in this repository. This document explains the core math, linear algebra, camera geometry, calibration logic, and how multi-tag fusion improves stability.

1) Current Implementation Status (Important)

Depth confidence usage

Current status: confidence frames are used in YOLO RGB-D localization to reject low-trust depth pixels (confidence >= confidence_floor) before 3D position estimation. They are not yet used for AprilTag pose gating.

Camera pose usage

Current status: camera pose is ingested into FramePacket, but the active calibration/anchor solver does not yet fuse Record3D camera pose into the final world estimate.

What currently drives world coordinates

  • AprilTag detections and per-tag pose estimates from pupil_apriltags.
  • Profile map of T_world_tag_i built during bootstrap.
  • Per-frame candidate fusion to estimate T_world_camera.

2) Coordinate Frames and Transform Convention

We use 4x4 homogeneous transforms in SE(3):

T_A_B = transform from frame B to frame A
p_A = T_A_B * p_B

Core frames:

  • camera: iPhone optical frame
  • tag_i: AprilTag local frame for id i
  • world: chosen as tag1 frame (origin policy)

3) Camera Model and Projection Math

Intrinsics matrix:

K = [[fx, 0, cx],
     [0, fy, cy],
     [0,  0,  1]]

Projection (camera -> pixel):

u = fx * X / Z + cx
v = fy * Y / Z + cy

Unprojection (pixel + depth -> camera):

X = (u - cx) * Z / fx
Y = (v - cy) * Z / fy
Z = depth

If RGB and depth resolution differ, intrinsics must be scaled to target image resolution. Otherwise one axis may appear wrong (common source of "one dimension off" bugs).

4) AprilTag Pose and Multi-Tag Fusion

Given detections in one frame, each visible tag yields a camera pose candidate:

T_world_camera_candidate(i) = T_world_tag_i * T_tag_i_camera
where T_tag_i_camera = inverse(T_camera_tag_i)

We fuse all candidates:

  • Translation: arithmetic mean.
  • Rotation: SVD-based orthonormal projection (average matrix then re-orthogonalize).
R_blend = sum(R_i)
[U, S, Vt] = svd(R_blend)
R_fused = U * Vt
if det(R_fused) < 0: flip sign on last axis and recompute

5) Why 3 Tags Are More Stable Than 1 Tag

  • Redundancy: if one tag is partially occluded, others still anchor the frame.
  • Noise averaging: independent pose noise cancels when fusing multiple tags.
  • Better conditioning: non-collinear tag geometry reduces ambiguity under oblique views.
  • Outlier detection: candidate disagreement exposes unstable solves.

For your policy (tag1 origin):

  • tag1 defines world origin and axis reference.
  • tag2/tag3 primarily improve stability and continuity.

6) Stability Metrics and Events

We compute residual spread between candidates:

trans_rmse = sqrt(mean(||t_i - t_fused||^2))
rot_rmse_deg = sqrt(mean(theta(R_i, R_fused)^2))

Quality score is derived from residual thresholds:

q_t = max(0, 1 - trans_rmse / trans_limit)
q_r = max(0, 1 - rot_rmse / rot_limit)
quality = 0.5 * (q_t + q_r)

Main events:

  • ANCHOR_UNSTABLE: residual too large
  • ANCHOR_HOLD_LAST: temporary tag loss, hold previous estimate
  • ANCHOR_LOST: no usable anchor estimate

7) Practical Example (Your Tag Layout)

Example session values in tag1 frame:

tag2 ~ (+0.118, -0.153, +0.007) m
tag3 ~ (-0.076, -0.142, +0.004) m

If these numbers are wrong in one axis, likely causes:

  • tag size mismatch (tag_size_m incorrect)
  • intrinsics mismatch or wrong resolution mapping
  • lens distortion not modeled
  • insufficient viewpoint diversity during calibration
  • origin tag not visible (falling back to mapped values)

8) Photography Concepts That Matter

  • FOV and distortion: wide lenses increase edge distortion; AprilTag corners become noisier near image boundaries.
  • Motion blur: blurred corners degrade tag pose solve; keep shutter high with good lighting.
  • Depth noise vs distance: depth variance grows with range and low-texture/reflective surfaces.
  • Exposure consistency: avoid aggressive auto-exposure swings during calibration capture.

9) Linear Algebra Concepts Used

  • Homogeneous coordinates for rigid transforms.
  • Matrix inversion for frame reversal (T^-1).
  • SVD for nearest valid rotation matrix projection.
  • RMSE residuals for candidate spread and confidence estimation.

10) Recommended Next Improvements

  1. Use depth-confidence map to mask low-trust regions before object localization.
  2. Fuse Record3D camera pose as a temporal prior between tag updates.
  3. Add radial distortion calibration/compensation for improved axis accuracy.
  4. Enforce direct-origin mode for coordinates when tag1 is visible.
  5. Log per-tag solve uncertainty and reject weak detections by margin threshold.
